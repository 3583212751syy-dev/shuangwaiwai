# 美客多 701 自动登记 · 独立升级版

复制自 `ml701-daily-autofill`，保留原目录。Windows 桌面自动化：紫鸟采集当天退货码及昨日营业额、广告费、点击，再写入钉钉表格。

## 本次修复

- 退货码页面：当前页没有授权码模块时，按可见名称选择销售/退货标签，再检查销售/退货导航入口，最多 6 个候选；不再只激活窗口后直接报找不到。只读取当日授权码标签附近的唯一代码，并修复稀疏 UIA 索引造成的漏读。
- 钉钉文档：固定入口缺失时，尝试有明确“搜索文档/搜索文件”名称的专用搜索框；不使用消息或聊天搜索。
- 单元格：优先通过可识别的可编辑名称框直接定位；Ctrl+F 不可用时，只读扫描 B2:B120 的 701，唯一匹配才放行。
- 填写入口：定位到目标格后，通过右移、左移及名称框回读验证网格确实接收键盘，再允许粘贴。名称框不可读或焦点未确认时停止。不会把附近任意文本或容器当作公式输入框。

- 缓存同时匹配运行日期与广告目标日期，禁止跨目标日复用。
- 从 A2:A40 读取明确日期，唯一匹配后才填写；不再按“日期号 + 1”猜行。读取失败、无匹配、重复匹配均停止广告写入。
- 日期支持年月日、ISO、中国月日、西班牙语月份缩写。无年份的月日按指定目标年份解释，因此仍需确保打开的是正确年度表格。
- 试运行采集失败返回失败，且文案明确未验证钉钉写入条件。
- 模块导入使用升级版本目录；状态和日志默认保存在本目录 `.workbuddy/tmp`，不读写旧目录凭证。可用 `ML701_STATE_DIR` 指定独立状态目录。
- 手动输入的退货码限 8 位十六进制；营业额和广告费非负，点击必须为整数。广告费 0–800 沿用原业务限制。
- 本地凭证不能掩盖实际单元格与旧码不一致的情况。
- 辅助脚本不允许独立启动，避免误执行历史补填入口。

## 使用

需要 Windows、Python 与 `comtypes`，紫鸟 G-701 和钉钉均已登录。不要与原版任务同时运行；本升级不修改现有计划任务。

```powershell
python -m unittest -v test_validation test_navigation
python daily_701_oneflow.py --probe
python daily_701_oneflow.py --dry-run
python daily_701_oneflow.py
```

`--probe` 只观察，不填写；`--dry-run` 可能切换采集页面并记录本地结果，但不写表格。最后一条才正式填写。手动数据参数：`--code`、`--data 营业额,广告费,点击`、`--date YYYY-MM-DD`。

若同日已经有成功凭证，默认跳过；显式提供 `--code` 或 `--data` 时会重新校验相应项。默认独立状态目录不继承旧凭证，因此首次正式运行需确认当日是否已由原任务处理。
