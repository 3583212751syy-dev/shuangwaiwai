# 库存核查规则与交付记录

更新日期：2026-11-21（Asia/Shanghai）

## 每次工作同步 Git 的约定

用户要求：每次完成的代码、规则、配置及模拟实施记录都同步到当前仓库。每轮完成时检查变更，只提交本轮相关文件，提交后从远端回读验证，并返回提交链接。没有变更时明确说明。同步失败时如实报告，不把本地保存说成已推送。不覆盖 WorkBuddy 或用户正在修改的内容。

本仓库为公开仓库。提交可复用逻辑、字段规则和执行状态；实时库存、原始表格、聊天记录、内部文档链接、凭据和个人信息不纳入提交。

## 库存检查字段规则

- 店铺编号精确匹配用户指定的目标店铺，排除其他店铺。
- 补货表中商品背景变橙色，或备注含“下架”，识别为缺货标记；以店铺编号和完整 SKU 比较新增、变化及恢复，不用行号作为身份。
- “通用品”检查整张 sheet，不限 SKU 前缀。A 列为可用库存，H 列为 SKU。
- SKU 单元格引用其他列，不代表被引用列为库存列。
- 目标为“每日检查库存”sheet：读取 A 列完整 SKU，把来源中当前可靠的可用库存填入同行 B 列；以实际表内列表为准。
- 完整 SKU 精确匹配，保留型号和变体后缀。重复匹配不得擅自合计；找不到、空白、冲突或读取失败时保留原值并报告，未知不能写 0。
- 橙色或下架状态与数值库存分别记录。标记缺货不意味着可以把来源数字改成 0。
- 钉钉相关库存不足、超卖消息应引发对应 SKU 重新核验。每日读取消息与实时事件触发属于两种不同能力，不能混称。
- 首次成功读取建立基线，不把已有标记全部报告为新增。只有成功读取后才能更新基线。
- 写入后保存并回读验证，保持工作簿其他内容及用户未保存的编辑。不自动调整商品、广告、价格或上下架。
- 参考现有退货码、广告费任务的单链路、精确定位 sheet、去重及写后回读方法，不运行或改写既有登记任务。广告费使用用户指定人员的 sheet。

1. 两个截图中有明确可用库存的 SKU 可以对应到目标同一 SKU 行的 B 列。

3. 其他 SKU 缺少当前可靠库存时不猜值、不填 0。
