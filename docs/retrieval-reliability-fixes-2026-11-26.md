# 第一批同款检索可靠性修复

日期：2026-11-26；基于 product-image-match 分支创建 fix/product-match-reliability。未部署线上，不表示新模型已接入或真实检索准确率已提升。

## 已实现

- Worker PATCH 保存并验证384维DINO向量、模型名和池化版本；只更新CLIP或标签时保留已有DINO。
- CLIP与DINO分别按产品组最高视图分排名，再以倒数排名融合，避免把不同量纲直接混为概率。一条记录缺DINO不会使全库关闭融合；缺失第二模型时以CLIP排名回退，仅用于排序，不声称双模型证据。
- 保留现有DINO池化，不混入未经重建的另一种特征。旧向量无版本字段仍兼容；显式不兼容的模型/池化不使用。
- 去掉z-score绝对阈值、领先倍数和近邻名称重复加信心。自动结果仅候选或疑似同款，需核对；不再凭低排名证据断言库里没有商品。
- OCR重复token不再推断商品件数。未验证OCR差异仅提示复核；必须两侧verified=true且同字段无歧义，才能排除规格冲突。显式verified数量可对比，普通文字次数不能。
- 规格检查扩展到候选池的全部已有角度；只有每个角度均有已验证冲突才排除整组。候选池为显示数量的4倍、最多64组，冲突候选后移再截取展示；缺失记录不冒充规格一致。
- 人工确认/否定保存查询图片SHA-256和产品组ID。同一字节内容图片再次检索时，最新确认优先、否定组过滤；旧文件名记录不直接套用。只是精确图片反馈复用，尚未训练可泛化的新模型。

## 验证

运行：node --test tests/product-match-regression.test.mjs

已在本机运行20项Node回归通过，覆盖混合DINO缺失、组内部分缺失、CLIP回退排序、非法向量、排名并列稳定性、分数非概率、人工反馈隔离与新旧记录兼容、重复OCR、多规格歧义、多角度未知证据、Worker写入后GET回读、保留原DINO和非法DINO拒绝等。ai-client.mjs通过node --check语法检查。

测试使用合成向量与内存Bucket，不运行真实视觉模型，不依赖外网。通过API回读不等于持久化存储重启验收；local-runner/server.mjs当前仍采用内存Bucket，服务重启持久化需要单独改造。

## 上线前剩余事项

- 真实展示图对实拍图库的独立评估尚未重跑。排名公式已改变，旧50.07%留一结果不代表此修复版，不能沿用为新效果。
- 真实浏览器上传、OCR模型加载、反馈操作和部署打包需端到端验收；本次仅源码及Node逻辑测试。
- 现有规格JSON没有verified字段的记录将作为提示证据，不自动否决；需后续人工证据或带位置/置信度的OCR结构完善。
- 接入Qwen精排、SigLIP2/DINOv3对照、商品主体裁剪、真实困难负样本基准属于后续模型验证阶段，本批不安装大型模型。
- 发布需重新生成嵌入脚本的app-worker.mjs；只更新源文件不会改变已运行网址。保留现网，验证后再发布。
