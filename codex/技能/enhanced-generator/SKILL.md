# 增强型内容生成器

## 核心原则

生成内容前，先**全面收集信息**，再**综合输出**。不依赖单一知识源。

## 工作流程

### 第一步：需求分析
1. 识别用户需求类型（技术文档/分析报告/代码/设计方案等）
2. 确定需要的信息源：
   - ✅ 网络最新信息（WebSearch + WebFetch）
   - ✅ 相关 Skills（自动匹配并加载）
   - ✅ 用户提供的内容/文件
   - ✅ 本地项目代码和上下文

### 第二步：信息收集（并行执行）
```
1. WebSearch - 搜索最新资料和最佳实践
2. 加载相关 Skills - 用 Skill 工具匹配并加载
3. 读取本地文件 - 用 Read 工具获取上下文
4. WebFetch - 抓取具体网页内容（如有URL）
```

### 第三步：智能生成
根据收集的信息，生成内容时遵循：
- **全面性**：覆盖所有关键方面，不遗漏重要信息
- **深度**：不仅说明"是什么"，还解释"为什么"和"怎么做"
- **实用性**：提供可执行的建议、代码示例、配置步骤
- **最新性**：基于搜索到的最新信息，标注信息时间
- **多视角**：从不同角度分析问题，提供多种方案

## 特殊能力

### 1. 网址学习内容
当用户提供网址时：
```
1. 用 WebFetch 抓取网页内容
2. 提取核心信息
3. 将信息融入生成的内容中
4. 可以批量处理多个网址
```

### 2. 多模型协作
根据任务类型自动选择最佳模型策略：
- **深度推理任务** → 使用深度思考模型（如可用的 o1/Gemini 深度思考）
- **快速代码生成** → 使用快速模型（DeepSeek V4 Flash）
- **复杂架构设计** → 使用最强模型（DeepSeek V4 Pro / Gemini 2.5 Pro）

### 3. Skills 自动匹配
根据用户需求，自动加载并使用相关 Skills：
- 前端设计 → `frontend-design`, `frontend-developer`, `shadcn`, `clean`, `dashboard`
- 全栈开发 → `senior-fullstack`, `test-driven-development`
- 调试问题 → `systematic-debugging`, `receiving-code-review`
- 研究分析 → `firecrawl-search`, `firecrawl-scrape`

## 输出格式

生成内容时，使用以下结构：

```markdown
# [标题]

## 📋 概述
[简要说明内容范围和目标]

## 🔍 深度分析
[基于搜索和技能的综合分析]

## 💡 解决方案
[具体可执行的方案，包含代码/配置]

## 📊 对比与建议
[多方案对比，给出推荐]

## 🔗 参考资源
[列出信息来源和进一步阅读]
```

## 质量检查清单
生成内容后，自检：
- [ ] 是否覆盖了用户需求的所有方面？
- [ ] 是否搜索了最新信息？
- [ ] 是否使用了相关 Skills？
- [ ] 是否提供了可执行的输出？
- [ ] 是否有清晰的结构和格式？

## 示例触发场景

✅ "帮我生成一个电商网站的技术方案"
→ 搜索最新电商架构 + 加载 `senior-fullstack` + 生成完整方案

✅ "分析这个网址的内容并写一份报告"
→ WebFetch 抓取 + 分析 + 生成报告

✅ "用最新的最佳实践重构这段代码"
→ WebSearch 搜索最佳实践 + 加载 `receiving-code-review` + 重构

✅ "给我一个全面的 AWS 成本优化方案"
→ 搜索最新 AWS 定价 + 多角度分析 + 具体优化步骤
